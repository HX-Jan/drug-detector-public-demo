# 毒品检测软件正式界面修改清单

日期：2026-10-17。依据：工作区《交互界面说明1.docx》的 39 张照片与操作说明、《交互界面说明2.docx》的 12 张照片与操作说明。本文为实施前设计，尚不表示功能已经完成。

## 已确认的范围

在现有 Java Swing 桌面端、原生 Android 和共享 core 上修改。保留两端技术框架，采用一致风格的线性图标，不引入 lucide-react。真实设备尚未提供协议，先建立可替换通信接口；未接入时保持未连接，禁止采集和生成判定。禁止通过本地生成信号补足设备响应。

工作区存在尚未提交的修改，实施时逐项增量修改，不回滚、不覆盖无关变更。保留历史文件，禁止在升级时直接删除用户记录。旧生成记录与新正式记录使用独立存储边界，禁止自动将旧记录转换成正式检测结果。

## 技术方案

采用共享业务服务、仓储与通信接口，桌面和 Android 分别实现界面与持久化适配。桌面保留原子文件写入，Android 保留 SQLite；二者均由仓储接口提供访问，不在界面构造记录。设备默认使用明确返回未配置错误的适配器，不返回设备列表、采集曲线或连接成功状态。

另一条可行路线是两端直接接入各自原生 USB/BLE，但需要实际协议与设备完成端到端验证。本次采用前一方案，通信接口包含发现、连接、断开、活化、扫描、取消、连接状态和设备能力。界面只接受业务服务的实际成功、进度与错误事件。

### 通用交互

按钮悬停使用浅底或加深主色，按下进一步加深，禁用使用浅灰并保留原因说明。输入聚焦使用蓝色边框，错误使用红色边框与字段提示。加载时禁用重复操作，但允许可取消操作退出；设备取消必须发送取消请求，不能仅关闭弹窗。鼠标与触屏操作均支持。

键盘 Tab 按界面顺序聚焦，Enter 提交当前可提交操作，Esc 关闭可取消弹窗；删除记录不绑定裸 Delete 快捷键。参考文档未定义右键菜单或拖拽，本次不增加。

### 区块比例

以 440×780 的归一化竖屏内容为参照：左右边距合计约 7.3%；页头约 12%；固定操作区约 9%；中部可滚动区域约 79%。首页设备状态、主按钮、三列入口沿纵向排列，每列占可用宽度三分之一；操作流不改为侧栏布局。

1440×900 桌面目标：保留参考的竖屏信息结构，内容容器居中，初始建议 500×860（视口宽约 34.7%、高约 95.6%）；外部留白保持中性白色。宽屏不横向拉伸表单和图表。桌面默认窗口调整为 1440×900，最小窗口允许中部滚动。Android 依据可用 dp 布局，在约 320–600 dp 宽保持单列；高度不足时只滚动正文，页头、操作区和键盘确认键可达。系统字号放大时允许文字换行，不能裁切。

## 数据模型

模型使用 Java 明确类型；所有 ID 为非空唯一字符串；时间为 UTC epoch milliseconds，界面按本地时区格式化。所有浮点输入均拒绝 NaN 和无穷大，缺值使用缺省状态而非数值零。保存包含 schemaVersion；读取执行版本与完整性校验。

| 模型 | 字段及类型 | 必填及校验 |
| --- | --- | --- |
| DeviceDescriptor | id:String、name:String、transport:Enum、address:String、capabilities:DeviceCapabilities | id/name/transport 必填；来源为适配器，不构造候选设备 |
| DeviceCapabilities | potentialMin/Max:double、maxPoints:int、supportedOperations:Set | 限制由协议提供；最小值小于最大值；maxPoints 至少为 2；未取得能力不能假定支持活化 |
| ConnectionState | status:Enum、deviceId:String?、connectedAt:long?、errorCode:String? | 断开、扫描、连接中、已连接、失败；已连接必须关联实际握手设备 |
| Sample | id:String、sampleNumber:String、projectId:String、reagentLot:String、createdAt:long | 编号 1–40 位字母/数字/下划线/短横线；批号去首尾空格后 1–64 字符；不包含控制字符；项目须有效 |
| StandardCurve | id:String、version:int、englishName:String、displayName:String、projectId:String、status:Enum、createdAt/updatedAt:long | 英文名字母起始，1–24 位字母/数字/_/-，不区分大小写唯一；版本正整数；状态草稿/生效/停用 |
| ScanParameters | start/end/peakStart/peakEnd:double、potentialUnit:Enum | start < end；start ≤ peakStart < peakEnd ≤ end；范围须在设备能力内 |
| ActivationParameters | start/end/step/rate:double、cycles:int、holdSeconds/quietSeconds:double | 起止电位不同；步进与速率 > 0；圈数正整数且在能力内；时间 ≥ 0 |
| Acquisition | id:String、deviceId:String、operation:Enum、startedAt/completedAt:long、potential:double[]、current:double[]、units:Enum、status:Enum | 采样数组长度一致且至少 2 点，有限值且在数量上限内；完成时间不早于开始时间；只使用真实采集值 |
| Baseline | acquisitions:List<Acquisition>、peakCurrents:double[3]、confirmedAt:long、confirmedBy:String | 正好三次成功采集；未确认不能拟合；变更基线清除下游草稿结果 |
| CalibrationPoint | concentration:double、repeats:List<Acquisition>、peakCurrents:double[3] | 浓度 > 0；三次完整采集；同一标曲浓度不重复；至少两个不同浓度才能拟合 |
| CurveFit | slope/intercept/r/min/max:double、baselineSnapshot:Baseline | 非零且符合方法约束的斜率；拒绝零方差；min < max；r ∈ [-1,1]；单位随快照保存 |
| DetectionLimits | method:Enum、values:double[]、mean/sd/lod/loq:Double | 手动 LOD > 0；自动必须正好 10 条；Sc 为样本标准差；LOD=2.82Sc；LOQ=4LOD；方法和原始值一并保存 |
| DetectionRun | id:String、sample:Sample、deviceId:String、curveSnapshot:StandardCurve、stage:Enum、createdAt/updatedAt:long、reactionDeadline:long? | 每次状态转移经服务校验；同一运行不可并发采集；快照不能随标曲修改而变化 |
| DetectionResult | id:String、runId:String、baseline/sample:Acquisition、deltaCurrent/concentration:double、judgement:Enum、qualityStatus:Enum、measuredAt:long、savedAt:Long? | 关联完整采集与快照；无规则则待判定；超出定量范围显示范围状态；保存幂等；不以保存成功替代检测成功 |
| JudgementPolicy | id:String、version:String、projectId:String、cutoff:double、unit:Enum、effectiveFrom:long | 所有字段必填且来源可追踪；未配置不猜测阴阳性阈值 |
| AuditEvent | id:String、runId:String?、entityId:String、action:String、from/to:Enum?、actor:String、occurredAt:long、reason:String? | 每次关键状态变化记录；跳过计时、授权、标曲修改和导出可追溯；不存口令 |
| AdministratorCredential | salt:byte[]、derivedHash:byte[]、algorithm:String、iterations:int、failedAttempts:int、lockedUntil:long? | 随机盐与 PBKDF2 摘要；不保存明文；首次设置与登录分开；失败次数和锁定持久化 |

## 状态与错误处理

检测流程：准备 → 活化中 → 等待第一次冲洗确认 → 等待加样 → 反应中 → 等待第二次冲洗确认 → 等待反应液确认 → 就绪 → 采集中 → 待保存 → 已保存。未完成状态可取消；设备错误进入失败并保留审计。重新采集必须明确开启新尝试，不能覆盖失败轨迹。

反应使用单调时钟；恢复时检查持久化期限与中断状态。跳过计时是文档明确存在的交互，记录操作者与时间，并将结果标记待复核；不通过短计时冒充完整反应。活化与采集进度来自适配器，不使用固定时长自动完成。

标曲流程：信息完整 → 参数完整 → 活化完成 → 基线已确认 → 浓度采集完成并拟合 → LOD 完成 → 保存。修改上游参数清除后续草稿采集，既有已保存版本不受取消编辑影响。自动 LOD 计算使用照片公式，科学方法有效性与设备性能仍须以实际方法验证。

空态使用“暂无检测记录”“暂无标准曲线”“未发现可用设备”；未接入使用“设备通信尚未配置”。加载使用“加载中…”或操作专用说明。读取失败提示“数据读取失败，请重试”，提供重试；损坏文件不按空库处理，不静默重置。写入失败保留原库和未保存内容。导出失败显示可操作原因，不显示堆栈。

## 验收范围

1. 编译并运行共享核心验证、桌面构建与 Android 可用构建检查。
2. 验证默认无候选设备、无预置标曲、无预置检测记录；任何界面路径都不能在未连接时生成采集或判定。
3. 检查两端可见字符串、应用标题、无障碍描述、导出表头，移除用户禁止的文案及调试入口。
4. 验证授权、字段校验、状态转换、上游数据失效、持久化重启、损坏数据读取与导出取消。
5. 检查桌面 1440×900 与窄屏、Android 紧凑尺寸的布局，核对 51 张参考材料覆盖的页面。
6. 硬件未接入的步骤只验证服务拒绝与界面错误反馈；不宣称完成实际设备、真实样本或性能验证。

## 已知差异和待确认项

- Java 技术栈与线性图标已获确认；不使用 lucide-react。
- 1440×900 与原竖屏照片比例不同，采用居中竖屏内容；具体容器尺寸为归一化建议。
- 照片无法精确提取无偏色的颜色、字体与像素尺寸；需要原始屏幕截图或设计资源才能做严格像素验收。
- 文档1正文提到第40张图，实际仅39个图片资源；以实际资源及正文行为共同覆盖，不虚构第40张图。
- 参考中的“样品测试”按用户禁用词要求改为“样本检测”；可见文字因此与照片存在明确差异。
- 设备协议、设备能力、实际 DPV 数据、厂家授权与判定阈值未提供；本次按用户确认，仅交付可替换通信接口，未接入不采集、不生成判定。
- 初始标曲库与记录为空，因此不复制照片中的药物列表、数值、设备身份和历史记录；项目由正式录入的标曲配置提供。
- Android 系统文件选择器、U盘挂载、厂商字体、设备权限和真实通信需要目标终端验证。
